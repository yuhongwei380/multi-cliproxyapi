# Multi CLIProxyAPI Controller

在一台 Linux 主机上统一管理多个 [CLIProxyAPI（CPA）](https://github.com/router-for-me/CLIProxyAPI) 实例。项目提供 Web 管理页面和 HTTP API，基于 CPA 构建总控服务，不修改 CPA 本身的代码。

每个实例拥有独立的二进制、配置、认证文件、日志和端口；总控重启或退出后，已经运行的子实例仍可继续提供服务。生产环境支持 **Linux amd64 + systemd**，使用单文件发布包，无需额外安装 Node.js。

当前版本：**26.10.13**。

本文是安装与使用入口。源码运行、测试、API 协议和发布流程请参阅 [开发文档](DEVELOPMENT.md)，源码部署及详细运维参考见 [部署文档](deploy/README.md)。

## 主要功能

| 功能 | 说明 |
| --- | --- |
| 多实例管理 | 创建、启动、停止、重启和删除实例，独立配置、端口与管理密码 |
| CPA 版本管理 | 下载并校验版本，统一升级，验证失败时回滚，保留实例原有运行状态 |
| 实例锁定与备份 | 防止误操作，手动备份，升级前自动备份，独立管理普通实例与备份名额 |
| API Key 管理 | 创建、分组、绑定多个实例，单独或按组下发与撤销，失败后重试 |
| 插件管理 | 为多个实例安装或升级插件，当前内置 Key Billing，支持部署记录和回滚恢复 |
| OAuth 额度观察 | 查看 Codex、Claude、Kimi 配额、重置时间和刷新状态，配置额度通知 |
| 日志与管理设置 | 查看运行日志、审计日志，修改管理员密码与实例名额 |

## 安装与首次使用

### 1. 下载并安装

从 [GitHub Releases](https://github.com/yuhongwei380/multi-cliproxyapi/releases) 下载 Linux amd64 的 `.tar.gz` 发布包并解压。目标系统需要 systemd、polkit（含 JavaScript 规则后端）和 logrotate。在解压后的目录执行：

```sh
sha256sum --check multi-cliproxyapi-linux-x64.sha256
sudo bash install.sh
sudo bash start.sh
```

安装脚本注册总控服务 `multi-cliproxyapi.service`，以及子实例服务模板 `multi-cpa@<instance-id>.service`。安装、启动、停止和卸载脚本均以 `sudo bash 脚本名.sh` 执行，root 用户可省略 `sudo`。

生产数据默认保存在 `/opt/mutli-cliproxycpa-data`，包括数据库、密钥库、CPA 版本和实例目录。如需指定数据目录或日志保留时间，在安装时设置：

```sh
sudo env MULTI_CPA_DATA_DIR=/srv/multi-cliproxycpa-data MULTI_CPA_LOG_RETENTION_DAYS=14 bash install.sh
```

### 2. 登录总控

在浏览器打开 `http://服务器地址:8787`。默认监听地址为 `0.0.0.0:8787`，首次登录用户名和密码均为 `admin`。登录后点击管理员头像，进入“管理员设置”修改密码；CPA 实例的默认管理密码也应修改。

通过防火墙或 HTTPS 反向代理限制总控及子实例端口的访问。经 HTTPS 反向代理访问时，可在 `/etc/multi-cliproxyapi/controller.env` 中设置 `MULTI_CPA_SECURE_COOKIES=true`，然后重启总控使配置生效。

### 3. 创建并使用实例

1. 在版本管理中确认已有可用的 CPA 版本；首次启动且没有版本时，总控会尝试下载最新版本，下载失败可在页面重试。
2. 创建实例，填写名称、未占用的端口和管理密码，再启动实例。
3. 从实例卡片进入 CPA 管理页面，配置上游服务或 OAuth 账户。
4. 在“API Key 管理”中创建 Key、绑定实例并执行“下发 Key”。绑定本身不会写入 CPA。
5. 客户端使用对应实例的地址、端口和已下发的 Key 访问 CPA 服务。

## 功能使用说明

### 实例锁定与备份

实例卡片提供“锁定实例 / 解锁实例”。锁定状态在总控重启后保留；锁定后禁止重启、停止、修改配置、备份和删除，统一升级或插件部署会跳过锁定实例。查看状态、刷新配额和启动已停止实例仍可使用。解锁需要总控管理员密码。

点击“备份”并填写新名称、新端口，可将当前实例保存为独立子实例。运行中的源实例会在复制期间短暂停止，复制结束后恢复；停止的源实例保持停止。备份保留 CPA 版本、配置、认证、插件数据和管理密码，不复制历史日志、进程 PID 和旧插件回滚目录。实例目录外的配置数据路径、符号链接和特殊文件不支持复制。

普通实例和备份分别计数，默认上限为 **5** 和 **10**，可在“管理员设置 → 实例名额”中调整为 1–1000，且不能低于已使用数量。启动、解锁或改名不会改变备份的名额归属。

### CPA 升级与恢复

统一升级只处理未锁定实例；所有实例都已锁定时，需先解锁至少一个。每个实例使用自己的 CPA 二进制副本，升级、回滚和总控重启均保留其期望状态，手动停止的实例不会被自动启动。

CPA 统一升级及插件统一安装 / 升级前，总控会为实际操作的实例创建独立备份，自动分配端口。自动备份默认停止并锁定，不会被后续统一升级选中。只有所有备份成功后才开始升级；名额不足或任一备份失败时中止，已创建的备份保留。单独下载或卸载未使用的 CPA 版本不会触发备份。

服务验证成功后自动清理本次备份；升级或验证失败时保留备份供恢复和排查。需要测试备份时，可解锁后启动；不再需要时，按实例删除流程清理。实例列表会显示备份来源和触发原因。

### API Key 管理

支持填写备注、手动输入或随机生成 `sk-` Key，以及复制、临时显示完整 Key 和搜索筛选。Key 在总控中加密保存，列表默认脱敏，审计日志不记录完整密钥。

- **分组**：新建组、编辑组名、调整 Key 归属；每个 Key 属于一个组，历史或未指定分组的 Key 归入“未分组”。删除组仅将组内 Key 移回“未分组”，保留 Key 和已有绑定。
- **绑定与下发**：一个 Key 可绑定多个实例。下发时保留实例已有 Key，跳过相同 Key，并读取确认结果。实例必须运行且未锁定。
- **批量下发**：选择组和目标实例，将组内全部 Key 添加绑定并下发；失败项保留绑定与错误状态，方便重试。
- **批量撤销**：从所选实例移除组内已绑定的 Key，成功后解除对应绑定，保留总控 Key 和组归属。组内含锁定或待删除 Key 时需先处理；失败项保留绑定供重试。
- **解绑与删除**：“解绑并撤销”仅处理指定实例；“删除”先逐个撤销所有绑定，全部成功后才删除总控记录。失败时可“重试删除”；待删除 Key 禁止新增绑定和再次下发。下发失败可“关闭报错”，处理实例后再次下发。
- **Key 锁定**：禁止修改备注、调整分组、新增绑定、解绑和删除，仍可复制、查看及向已绑定实例下发；解锁需要总控管理员密码。

撤销需要目标实例运行且未锁定。若撤销后 CPA 客户端 Key 列表为空，总控会写入一个不向用户发放的随机保护 Key，避免实例因空列表而允许匿名访问。

实例备份会继承总控 Key 绑定。保留备份且需要撤销其中的 Key 时，须先启动并解锁备份；不再需要的备份可直接解锁并按实例删除流程清理，无需先启动或手动解绑。删除实例成功后会清理其绑定，保留 Key 本身及其他实例的绑定。未绑定到总控的独立 Key 或历史副本不在撤销范围内。请避免同时在 CPA 原生面板和总控中修改同一实例的 Key 列表。

### 插件管理

在插件管理页面选择版本和目标实例，可统一安装或升级当前内置的 **cpa-key-billing（Key Billing）**。版本留空时获取最新发布版本，下载包经过校验后缓存，各实例保留独立插件文件。

已锁定实例会跳过。备份完成后，运行中的实例逐个短暂重启并验证；停止的实例保持停止，标记为待启动验证。默认保留原有启用配置，勾选“安装后启用”才写入启用配置；未启用的插件验证通过后显示“已安装，未启用”。新建实例默认开启 CPA 插件支持。

首个部署失败会回滚当前实例并取消后续部署，已成功的实例保留新版本。总控重启后会恢复未完成的切换，回滚失败时可点击“重试回滚”。回滚恢复插件文件和 CPA 配置，无法逆转插件自身的数据迁移；完整旧数据保留在升级前的备份子实例中。

部署记录可查看时间、状态、逐实例结果及对应备份。完成或失败的记录可确认删除；排队、执行中或等待恢复的记录不能删除。删除记录不会卸载插件或删除实例配置、备份。

### 额度观察与通知

总控通过 CPA 本机管理 API 获取 **Codex、Claude 和 Kimi OAuth 配额**，默认每 6 小时刷新。Kimi 支持周限额、滚动窗口及接口提供的月限额。总控不读取认证目录、不保存 OAuth Token，也不调用额度重置接口。

“额度观察”和实例详情展示账户、额度窗口、使用百分比、进度条及重置时间。查询失败时保留上一次成功快照并显示失败状态。

额度通知按实例、账户和额度窗口附带刷新时间（UTC+8）；未提供有效时间时明确标注。“发送测试消息”会实时读取目标实例的周额度和重置时间，沿用正常告警格式并加上【测试消息】。全局测试使用已保存的全局目标实例；测试不受额度阈值、工作时间或冷却限制，也不占用正常告警冷却时间。

### 运行日志与审计

Web 页面提供运行日志和审计日志。运行日志支持按总控、实例、CPA 升级、插件安装、API Key、额度通知和 HTTP 分类，并可组合级别筛选、关键词搜索、刷新和展开详情。服务端按分类及级别筛选后返回最近 500 条，运行日志最多保留 10000 条。

日志记录升级、回滚、插件部署、Key 下发 / 撤销及额度通知的结果；相关操作日志保存标识和计数，不复制密钥、Webhook 地址或上游错误原文。

## 日常运维

在发布包目录执行以下脚本：

```sh
sudo bash start.sh
sudo bash stop.sh
sudo bash uninstall.sh
```

`start.sh` 和 `stop.sh` 只控制总控，已经运行的 CPA 子实例保持独立。修改总控环境配置后，可执行 `sudo systemctl restart multi-cliproxyapi.service` 重启总控。

systemd 安装默认将总控日志写入 journal 和 `/var/log/multi-cpa.log`，日志等级为 `info`。可用 `sudo journalctl -u multi-cliproxyapi.service -f` 查看实时日志。日志轮转配置位于 `/etc/logrotate.d/multi-cpa`，默认保留 7 天；`MULTI_CPA_LOG_LEVEL` 支持 `debug`、`info`、`warn`、`error`。

卸载前请先停止所有 CPA 实例。只要仍有实例运行、正在启停或无法确认状态，卸载脚本就会拒绝继续。确认移除服务和二进制后，还需输入完整数据目录才能永久删除数据；拒绝第二次确认会保留数据。
