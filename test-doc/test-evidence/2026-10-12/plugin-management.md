# 总控统一插件管理验收

日期：2026-10-12。环境：Ubuntu 22.04.5 amd64、systemd、Node.js 24.18.0；CPA 8.0.23（d318bcc3），Key Billing 1.3.19 / 1.3.20。仅操作测试实例 `cpa-812f1d284bb14a0ba06d`。

## 实现范围

- 插件管理页面、插件清单、版本输入、实例选择、锁定跳过预览、独立“安装后启用”选项、部署记录和回滚重试。
- 经过审核的插件描述驱动通用下载、SHA256 校验、ELF 检查、缓存、独立分发、备份、逐实例加载验证及恢复流程。
- 后端任务持久化；与实例及 CPA 升级操作互斥；保留停止状态、现有配置与启用状态。首个失败回滚当前实例并取消后续部署。
- 启动时恢复中断任务，无法完成回滚时进入 blocked 状态，不允许继续修改实例。
- 不执行远程安装脚本，不调用匿名 GitHub API。回滚不逆转插件数据库迁移。

## 验证结果

Linux 后端全套 **120 / 120** 通过；前端全套 **30 / 30** 通过。新增后端覆盖配置编辑、锁定跳过、运行验证、失败回滚、后续取消、恢复重试、校验失败、缓存篡改及备份失败；新增前端覆盖部署参数、锁定预览和恢复入口。

真实服务器端到端 **8 / 8** 通过（原始任务结果见 `plugin-management-results.json`）：

1. 移出既有插件文件，确认未安装，然后通过总控首次安装 1.3.19；配置逐字节相同，实例保持停止。
2. 锁定实例后提交部署，确认跳过，插件 SHA256 不变。
3. 启动后管理 API 确认实际加载 1.3.19。
4. 运行中升级到 1.3.20，注册与版本验证通过，配置逐字节相同。
5. 勾选安装后启用，管理 API 确认 effective_enabled。
6. 用测试专用缓存把实际 1.3.19 库标记为 1.3.18，触发真实加载版本校验失败；旧库、配置和运行状态恢复，实际版本回到 1.3.20。
7. 在上述校验阶段 SIGKILL 总控；systemd 重启总控后恢复持久化任务，回滚成功，实例仍运行 1.3.20。
8. 通过总控停止实例，确认停止状态。

模拟的 1.3.18 缓存仅用于版本不匹配测试，已移除；未声称对真实 1.3.18 版本做兼容性验收。没有模型供应商或 OAuth 凭据，因此不包含真实请求计费验证。
