## 真实走测

1. 管理员鉴权、手动创建、随机生成、备注、列表脱敏和重复创建拒绝。
2. 同一 Key 绑定两个真实实例，绑定后配置不变化；下发后客户端 `/v1/models` 使用该 Key 返回 200。
3. 重复下发显示已存在，每个实例只保留一份该 Key；原有独立 Key 保留。
4. Key 锁定拒绝删除与撤销，错误管理员密码拒绝解锁；实例锁定拒绝下发。
5. 单实例解绑实际从该 CPA 删除 Key，旧 Key 请求返回 401/403；其他绑定实例继续保留它。
6. 一个实例停止后全局删除部分失败，保留剩余绑定和待删除状态；SQLite 重开仍能读到失败状态。启动该实例后重试完成删除。
7. 移除最后一个 Key 时保留未发放的随机保护 Key；旧 Key、匿名请求和错误 Key 的实际请求均被拒绝。
8. 手动及自动备份继承绑定，备份配置确实包含原 Key；停止或锁定的备份阻止全局删除。启动并解锁后，备份和来源均实际撤销该 Key，原有独立 Key 保留。
9. 并发下发不产生重复。关闭并重建总控、重开数据后，备注、加密 Key、锁定与绑定保留，CPA 子进程继续独立运行。
10. 审计不含完整 Key、管理员密码或 CPA 管理密码。

## 联调发现并修复

CPA 8.0.23 的 `/v8/management/config/access/api-keys` 返回 404，本轮实际使用 `/v0/management/api-keys` 回退。该版本的空列表返回 `{ "api-keys": null }`；原解析只接受数组，会拒绝新实例。现在将明确的 null 列表归一为 `[]`，仍拒绝缺失字段和错误响应，并补充回归测试。

此次实测覆盖 CPA 8.0.23 的旧接口回退；v8 接口契约由单元测试覆盖，未在另一实际 CPA 版本上验收。未调用供应商模型推理、OAuth 配额或计费业务。正式服务和既有数据没有替换；独立验收源码与无凭据报告保留在测试目录。

## 复现

使用 Node.js 24 和已构建的 `web/dist`，在 Linux 中运行：

```sh
CPA_TEST_BINARY=/absolute/path/to/cli-proxy-api CPA_TEST_VERSION=8.0.23 node scripts/verify-key-management.mjs
```

脚本自动创建独立临时数据和随机端口，运行后清理自身创建的 CPA 实例。可用 `CPA_E2E_EVIDENCE` 指定报告路径。临时管理员和管理密码默认随机生成，不读取正式总控凭据。
