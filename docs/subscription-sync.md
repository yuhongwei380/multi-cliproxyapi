# Key Billing 自动统一周期同步

仅修改总控，使用未修改的原版 Key Billing 管理接口，无需扩展插件。已用原版 1.4.17（源码提交 `6314edd018a94eee240f8266eb9eab20db62b475`）和 CPA v7.3.7 完成本地联调。

## 触发与日期选择

- 启动后通过实时周／月额度查询建立观察记录。每个实例独立记录全部账户中即将到来的最早重置日期及其账户、窗口。
- 首次查询只记录未来日期，不通过减去 7 天或 30 天推断“刚发生过重置”。尚未观察到旧日期时不会补触发。
- 默认自动观察各实例，不依赖是否配置额度通知或 Webhook。沿用原额度查询周期，并将额外查询提前至观察到的最早日期；官方数据未及时更新时，窗口内每分钟查询一次。
- 只有在已记录的重置时间至该时间后 15 分钟以内，全部账户查询成功、所有相关日期均有效且在未来、原账户和原窗口仍存在且日期已经进入下一轮，才执行订阅同步。
- 实例有两个或更多账户时，也只取最早时间作为本轮触发点。执行时再次从本次实时结果选择即将到来的最早日期，作为全部计划窗口的下次重置时间。
- 超过 15 分钟窗口就跳过，不补清零；改为观察之后的最早日期。观察记录和执行进度保存在总控数据库，重启后保留。
- 页面只提供自动同步状态和“刷新同步状态”；该刷新只读插件计划，不查询上游额度、不修改额度。`GET /api/instances/:id/subscription-sync` 为只读接口，POST/PATCH 等手动操作均返回 405。

## 调用原版插件

1. `GET /v0/management/plugins/cpa-key-billing/plans` 读取全部计划。所有计划必须使用统一周期、每个 Key 独享额度；存在独立周期或共享额度计划时停止，不转换模式。
2. 全部窗口先检查：目标日期在未来、且不超过该窗口一个完整周期。原版只接受秒精度，不足一秒的部分舍去。所有计划都检查，包括暂未绑定 Key 的计划。
3. 逐个 `PATCH /v0/management/plugins/cpa-key-billing/plans`，仅传计划 ID 和完整窗口设置，将 `cycle_anchor_at` 设为目标日期。保留窗口 ID、名称、时长和额度上限，不传 Key 绑定列表。
4. 重新读取并核对所有计划，再 `POST /v0/management/plugins/cpa-key-billing/keys/reset`，参数 `{"mode":"global"}`，清空本实例全部订阅额度。等价的时间表编辑不会清零，所以仍需要全量重置。
5. 再次核对计划，记录完成时间、本轮触发日期、计划数、计划窗口数和下一次重置日期，并写入运行日志及 system 自动操作审计。

每次写操作前都检查 15 分钟截止时间，等待锁或更新多计划期间超时也停止，不继续发出写请求。请求本身的处理完成时间受网络和插件影响，无法跨进程保证恰好在截止前落盘。

例如先观察到账户在 11 月 6 日 08:00 重置，08:01 查询确认日期已进入下一轮；若全部账户新的最早日期是 11 月 13 日 08:00，则把所有计划的下一次统一重置设为该时间，并清零当前额度。7 天窗口对应 11 月 6 日至 11 月 13 日，30 天窗口对应 10 月 14 日至 11 月 13 日。每个 Key 仍独享额度，首次使用不会推迟统一周期边界。各窗口之后按自己的固定时长延续，直到下次自然重置事件再次同步。

## 限制与失败处理

- 包括 Claude 细分周窗口；相关日期缺失、已过、任何账户查询失败或不支持时不执行，不使用缓存来确认自然重置。
- 原版按固定秒数计算周期，30 天不是自然月。若存在 7 天窗口但最早日期在 10 天后，在任何修改前拒绝，不擅自改变周期长度。
- 实例停止、锁定、升级或插件部署中时不修改。未发出写请求的条件失败可在剩余窗口内重新检查。
- 总控操作锁防止自身操作冲突，但无法锁住用户在插件页面直接进行的计划或 Key 绑定编辑。执行期间应避免同时编辑；计划核对不一致时停止。
- 原版没有跨计划事务，更新某些窗口的日期时可能已经清零这些窗口；后续失败不能保证整体回滚。
- 首次写请求前持久化本轮事件及执行阶段。一旦尝试写入，同一事件不自动重发；断网、异常响应、部分失败或总控重启都不会重复清零本轮额度。
- 页面保留未确认提示供核对；之后另一轮自然重置可以正常触发。未知来源的旧未确认操作没有事件日期时，自动写入保守暂停，需先核对并处理旧状态。
- 历史用量记录保留。完成记录展示计划数与计划窗口数，不把原版全量重置返回的零计数误认为受影响 Key 数。

## 验证

```bash
node --test --test-concurrency=1 server/*.test.js
npm run build
npm --prefix web run test:run -- --maxWorkers=1
```

使用原版插件二进制进行真实 CPA 本地联调（仅访问本地模拟上游，OAuth 额度日期使用模拟快照）：

```bash
CPA_SYNC_TEST_BINARY=/path/to/cli-proxy-api \
CPA_SYNC_TEST_LIBRARY=/path/to/original/cpa-key-billing.so \
node --test server/subscription-sync.integration.test.js
```

验证实际额度查询调度器、总控实例锁、两个统一周期计划、两个 Key、四窗口日期与额度、插件重启持久化、重复查询与总控重启不重置、手动接口不可用，以及非法目标在任何写入前被拒绝。
